The intact preserved 2002 application uses x87 control word `0x027f`: 53-bit arithmetic, nearest-even rounding and masked exceptions. The live original CRT selects this mode before game code. Hardware execution breakpoints measured the same word after CRT setup (`0x457054`), before the paint wrapper (`0x403bb0`), before the complete frame (`0x404020`) and before scene composition (`0x404880`). Every observation verified all original `.text` bytes against the preserved executable.

The probe used the normal Wine loader and original CRT/MFC lifecycle. It never wrote target instructions, game data or the target control word. Normal Space key events passed the original startup notice and start gates. The hardware debug registers were cleared and the debugger detached; the original app remains running. No other Wine prefix was touched. Exact observations, tool hashes and scope are recorded in [startup-precision.json](startup-precision.json). The [probe source](../tools/native_startup_precision_2002.c) uses the Windows [debug-event loop](https://learn.microsoft.com/en-us/windows/win32/debug/writing-the-debugger-s-main-loop) and [thread context](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getthreadcontext) APIs.

Separate actual-hardware reference data is in `assets/data/pc53/`, with hashes and repeatability evidence in [pc53-assets-reference.json](pc53-assets-reference.json). Original `0x415a60` supplies integer lookup tables and original `0x417790` supplies binary64 boat calibration under `0x027f`. The standalone opcode probe captures the finite extended/stored/hull/raw/force trigonometric domains. Existing `0x037f` assets and fixture claims remain unchanged and describe isolated 64-bit arithmetic, rather than the live app's startup context.
